# Changelog

Notable changes to Factwright, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning](https://semver.org/).

## Unreleased

## 0.9.1 - 2026-10-18

### Fixed
- On a Mac, Factwright no longer reaches into your browsers' folders as it starts. To set up saving from Save to Factwright straight to this computer, 0.9.0 looked in each browser's folder, which macOS keeps to that browser: it blocked Factwright and said "Data Access Blocked", even for people who never use the extension, and no browser was set up. Now Factwright finds your browsers by their apps in Applications, and reaches a browser's folder only when you set that browser up.

### Added
- A Save to Factwright window, from Browser extension in the sidebar: what the extension does, where to get it, and where each browser on this computer stands for saving straight to Factwright here, with no account and no sync. On a Mac, Set up beside a browser adds the small file that browser finds Factwright by, and the window says first that macOS asks you, once for each browser. If you choose Don't Allow, or macOS blocks it, the window says so, with the steps to allow it in System Settings, under Privacy & Security, then Files & Folders, a button that opens it, and Try again. On Windows, Factwright still tells each browser as it starts, and the window shows them ready. The sidebar's link opens the window whatever sync is doing, as saving to this computer needs no sync.

### Changed
- When Save to Factwright can't find Factwright on this computer, it says that on a Mac you then set up the browser from Browser extension in Factwright's sidebar. This reaches the stores with the extension's next version.

## 0.9.0 - 2026-10-18

### Added
- Save to Factwright can save straight to Factwright on the same computer, with no account and no sync, so the extension is free for everyone. Setup asks where saved jobs go: Factwright on this computer, or through sync, for Factwright on another computer. For this computer, the browser asks once to let the extension talk to apps on the computer, and it talks only to Factwright: Factwright installs a small helper, signed with the app, and registers it with Chrome, Edge, Brave, Arc, Vivaldi and Firefox when it first starts and after each update, for Save to Factwright alone. The helper takes only a job's title, company, pay, link, site and posting, and drops it in the open profile's inbox in Factwright's data folder. Factwright adds it as New, with its posting, at once if it's open, and says so in the popup, or the next time it opens. Saving the same job again adds it once. Uninstalling Factwright on Windows takes the registrations away. This reaches the stores with the extension's next version, and this release carries the helper.
- Save to Factwright signs in through the browser's own window for extensions, with no code to compare. Sign in to sync opens your sync server's page in a window of its own: signed in there already, it asks once, naming the account, and otherwise you sign in first. Allow, and the window closes and setup goes on to linking. Don't allow, or close the window, and nothing signs in. The answer is a one-time code that the browser hands to that extension alone, and only it can use. Neither Chrome nor Firefox shows a warning for the new permission, so the update asks nothing. Factwright's sync still signs it in with a code for a copy it doesn't know, such as one you built yourself, or when the window can't open, and Save to Factwright 0.1 always does. A server of your own signs it in through the window alone: a code shown for your server could be one it got from Factwright's sync and passed along, for you to allow there, while the window's answer names the server that gave it. So your server needs a version with the window, as setup says when it hasn't, and a copy you built yourself needs its ID in the server's `EXTENSION_IDS`, which setup names. Factwright's sync has it, so it's live once the extension's 0.2.0 reaches the stores.
- Paying for sync, ready for when Factwright's server sells it, as it doesn't yet: $5 a month or $50 a year, while a server of your own stays free. Signing in to Factwright's sync then leads to Subscribe to sync, which opens Factwright's page for it in your browser, where Stripe takes the payment, and carries on by itself once you've subscribed. Accounts with free sync, or from before it was sold, skip it. When a subscription ends, sync pauses on each computer, keeping the job hunt there, and picks up where it left off once you subscribe again. A card that didn't go through shows on the Sync card while sync carries on. The Sync screen says when the subscription renews or ends, with Manage, and the web view's account page shows it and opens Stripe's page for managing it. The phone says when sync is paused, and how up to date the job hunt is. Save to Factwright's setup says when sync needs a subscription, instead of asking Factwright to link it, and a save while sync is paused saves nothing and says why. Each place keeps "Money's tight? Email steve@factwright.com and I'll turn on sync for free" and the steps for a server of your own.
- Sync through a server of your own. Turning sync on offers Factwright's sync and your own server side by side, with a link to the steps for running one for free in your own Cloudflare account. Connect your server… takes its address, checks it's a Factwright sync server that's up to date, says to use only a server you run or trust, and signs in to it through your browser, with no code to compare: your server's page names the account, you allow it, and your browser comes back to Factwright on your computer, which takes the answer only from the server it asked. A code shown for your server could be one it got from Factwright's sync and passed along, for you to allow on Factwright's own page, where it would match. So your server needs a version with this, as Connect says when it hasn't, and Copy the link opens the page only in a browser on the same computer. The sign-in step and the Sync screen name the server, and to switch to another, you turn sync off on this computer first. Its sign-in is kept with its address, so it never goes anywhere else. Any copy of Factwright can do it, including one built from the code, which offers only a server of your own.
- The sidebar links to the browser extension, Save to Factwright, beside Support Factwright, so it's always a click away. It's left out with a server of your own, and in a copy without Factwright's sync, since the extension saves through Factwright's sync for now.
- factwright.com's header has a Browser extension button beside GitHub, on screens wide enough for it to sit beside the page's links.
- A server of your own can be yours alone. `ALLOWED_GITHUB_USERS` lists the GitHub accounts that may sign in to it, and the Deploy button asks for it: your GitHub user name, and anyone else's after a comma. Anyone else is turned away with a note that the server is private, before an account is made, so no one else's files count against your Cloudflare allowance. Unset, anyone with GitHub can sign in, as on Factwright's own server, which stays open to everyone. factwright.com/own-server's steps and questions say so.
- factwright.com/own-server, a guide to running your own sync server in a free Cloudflare account, in about 15 minutes and with no code to write: find your workers.dev subdomain, make a GitHub sign-in app, deploy with Cloudflare's Deploy button, and connect Factwright. Type your subdomain, and the page fills in every address for you to copy. It makes the server's secret in your browser, and sends nothing anywhere. It says up front that Cloudflare may ask for a payment method before it turns on R2, its file storage, and that updates to your own server aren't automatic yet. The site's footers and the home page link to it. It goes live with the site's next update.
- Save to Factwright can sync through a server of your own. Setup asks which sync Factwright on your computer uses: Factwright's, or your own server, by its https address, with no path or login in it. For your own, the browser asks once to let the extension reach that one address, nothing more, and setup checks it answers as a Factwright sync server before you sign in there. The extension's sign-in keeps its server, so what it saves goes only there, and it gives the browser's permission back when you sign out, or when signing in there fails or is canceled. Setup remembers your choice, the account section names the server it saves through, and "Turn on sync first" can sign out, for when Factwright on your computer syncs somewhere else. This reaches the stores with the extension's next version.

It's live on Factwright's sync, and on a server of your own once it's updated.

A server of your own could get a code from Factwright's sync and send the extension's sign-in window there for you to allow it. It's live on Factwright's sync, and on a server of your own once it's updated.
- When Save to Factwright signs in with a code, as its 0.1 versions do, the page where you sign in says it's for the extension, and to sign in with the account Factwright on your computer uses. Before, it said Factwright on your computer was signing in. The sync server names who asked for the code in the page's address, so no new app or extension is needed. It's live on Factwright's sync, and on a server of your own once it's updated.
- The page where you let the desktop app or the browser extension sign in says which account it signs in to. Signed in to the wrong one, Use another account signs you out there and in with another, then comes back to the same code to allow. It comes back to the page you started on, so the code the desktop app or the browser extension showed is still there to approve once you try again. - factwright.com/extension links to Save to Factwright in the Chrome Web Store, now that Chrome has approved it, and the site's other mentions of the extension no longer say it's coming soon. Firefox's button says it's coming soon to Firefox Add-ons until that store approves it too.

### Fixed
- A cover letter's PDF reads from the top: a system that reads its text, such as an applicant tracking system, now gets your name, headline and contact details first, then the date, the recipient and the letter. Before, it got them last, in every template. Nothing moves on the page in Factwright's own templates, and lines break where they did. Letters built before read as they did until they're built again.

## 0.8.0 - 2026-10-16

### Added
- Claude Code's permission prompts in a dialog of their own. When Claude Code asks your OK before Claude goes on, such as to read a web page, change one of your facts, save to your profile or save a template, Factwright asks it in a dialog, in plain words and in full: the file and the text a change takes out and puts in, all of what a new file holds, a page's whole address and the site it goes to, what goes in your profile field by field, including any it clears, or a template's name and ID, the template of yours it replaces, and its whole file. Allow lets that one call through. Don't allow tells Claude you said no, with anything you add, and Claude carries on without it. The dialog never offers to allow anything for good, so what Claude may do without asking stays as you set it. Claude Code's own prompt is still in the terminal behind it, and whichever you answer first counts.
- Questions that ask for a number or a line of words open in the questions dialog too: a box for the number, with its unit and any number Claude suggests as a hint, which Send waits on until it's in the question's range, or a box for your words.
- When only the terminal can answer, as for Claude Code's first question about trusting your workspace, or a question you sent there, the terminal gets an outline that pulses a few times, and a note above it points down to it and says how to answer with the keyboard. The first time, the note also says this is your own Claude Code, until you choose Got it.

## 0.7.0 - 2026-10-16

### Added
- Claude's questions in a dialog of their own. When your Claude asks you something while it works, such as whether you've used a skill a posting wants, the questions open in Factwright rather than in the terminal: all of a round at once, each option with what it means, a box for your own words when no option fits, several picks where Claude allows them, and a note for Claude about any answer. Your answers go straight to your Claude Code, which notes them in Claude's panel as before. Not now puts the questions aside, still waiting, with Answer in Claude's panel to come back to them, and Answer in the terminal has Claude Code ask them there instead. The dialog waits up to a day for you. A question Claude Code asks in a way of its own, such as for a number, still comes in the terminal, and facts are filed from your answers just as before.

## 0.6.0 - 2026-10-16

### Added
- Calls and interviews, step by step. Each job's calls have a section of their own, in the order they happen: what kind of call it is, when, for how long, by phone, video or in person with its link, number or address, who it's with and their roles, and what it's about. Everything can be changed later, a call can be canceled, and deleting one asks first. The next call booked is marked Next, an https meeting link opens with Join, and the form starts on the round after the last one, with the people you've met there to pick from.
- Call prep. A button on each call coming up has your Claude write a prep sheet for that call, kept with it: what to land in the five minutes before, what the round is for and how it usually goes, who you're meeting from public pages (never LinkedIn's own), what happened in the earlier rounds, likely questions with answers from your fact bank, stories to have ready (on a panel, which story for whom), gaps and how to handle them, questions to ask each person, and pay and logistics. Each call keeps its own sheet, so the next round's prep builds on the last. Practice runs a mock interview for the call, playing the people on it.
- How it went. Once a call's time comes, it asks how it went, with a box for your notes, which the next round's prep reads, and Add the next round once it moved forward. Thank-you notes has your Claude draft one for each person you met, from your notes, each with a subject and Copy, for you to send yourself.
- Needs you says "Prep for the panel interview tomorrow at 2:00 PM" when a call two days off has no prep sheet yet.
- Add to calendar. Each call coming up has Add to calendar, which saves a calendar file (.ics) for it where you pick, to open in your calendar app or import into Google Calendar: what it is and who it's with, its day and time as you gave them, for its length (an hour if you didn't say), with the meeting's link or the address, and the role, who it's with and what it's about in its notes. The file only adds the call to your calendar: it invites no one, so nobody on the call hears from it. A call with no time is an all-day event.
- Fill in a call from its invite. Drop the invite's .ics file from the company's email on the Add a call form, or pick it with Fill in from an invite, and the form fills in the date, time, length, meeting link or address, and who it's with, leaving out you, rooms and anyone who said no. The time is put in your computer's time zone, and the form says to check it when the invite's zone can't be read. People you've met at the company bring their roles. The invite is read on your computer, with no Claude and nothing sent anywhere, as plain words only, cut to the form's limits, and the only link kept is an https one.
- A reminder an hour before each call that has a time: "Panel interview with Northwind Labs at 2:00 PM", and whether your prep sheet is ready. Clicking it opens the job. It comes while Factwright is open, even in the background, once per call, or as soon as Factwright looks again if the computer was asleep, until the call starts. The next call says a reminder is coming, with Turn off, which turns reminders off on that computer.
- Your phone shows each call's details, Join for its link, and its prep sheet and thank-you notes, once the sync server is updated.
- For Claude, `job_details` lists each call with its ID, who it's with, how long and how, what it's about, how it went and its prep sheet, plus the user's other jobs at the company, and `save_call_prep` and `save_thank_you` save a call's prep sheet and thank-you notes in its own folder, `calls/<job>/<call>/`.

### Changed
- Activity is now History, and covers the whole company: each call with who was on it and how it went, your notes, each change of status and Claude's work, across your jobs there, with the people you've met at the top.
- Calls moved from Progress to their own section, where Log a call is now Add a call. Saying how a booked call went marks it done.
- A computer still on an earlier version keeps a call's new details when it changes the call, and shows them once it updates.

### Fixed
- Each account's daily cleanup on the sync server keeps to its schedule when a day's run fails: the next day's is planned and saved before each one runs, and a failure is written down. Before, a cleanup that failed several tries in a row, or never finished, stopped them until one of the account's devices synced a change, so an account no longer in use could keep earlier versions past the 90 days the privacy policy keeps them.
- Save to Factwright 0.1.1 reads job sites as they are today, checked in real Chrome and Firefox. It reads Indeed's job pages, and the job beside its search results, in Indeed's current layout, where before it found neither the job nor the posting. A Hacker News "Who is hiring?" post is read by itself, on its own page or as the post you selected text in, with the company and title its first line names and the post's own link, where before it took the whole page, with "News" as the company. Greenhouse job boards give the company's name as the board writes it, not as its address spells it, Workday gives the company without the legal entity's code ("NVIDIA", not "2100 NVIDIA USA"), and SmartRecruiters' postings leave out the buttons and links after them. These reach the stores with the extension's next version.
- On a Mac, Factwright's window comes back after you close it, from the Dock or by opening the app again, even once the app has made a resume, a cover letter or a template's preview, where before nothing happened, and from one of its notifications, where before that showed an error. On Windows, closing the window quits Factwright even once it has made one of those: before, it kept running unseen, and opening it again showed an error.
- An installed copy of Factwright started with a debugging port, as its tests are, never asks the keychain for sync's keys. Sync can't turn on in it, and sync's keys in its data folder, even ones copied or linked from your own, stay locked and as they are. Before, on a Mac, it used the same Keychain item as every other copy, yours included.
- Documents shown in the app and on your phone, such as fit checks, answers and saved postings, can no longer freeze the window, however long or odd they are: each is now read once, a character at a time. Before, a heading with a Unicode line separator (U+2028) in it kept the window busy until it ran out of memory. A line of 100,000 spaces under a table's first line took 11 seconds, and a list item with as many spaces and a line separator took seconds too. So did a table thousands of columns wide over thousands of short rows, filling the rows out with millions of empty cells: short rows are now filled out with at most 10,000 empty cells, or one for each character of the document if that's more. A heading or list item with a line separator in it now shows as one, and everything else shows as before.
- PDFs of resumes and cover letters hold letters such as fi, fl, ff, ffi and ffl as the letters themselves, so applicant tracking systems read every word. Before, in a template set in Factwright Sans, Calibri's stand-in, as many of your own are, in headings set in Barlow, and in Classic's italics, a system could read "first" as "ﬁrst", with a character it doesn't know, and miss words such as certified and profile, or a heading such as Profile. They look the same on the page, and lines break where they did. Resumes and letters built before keep those characters until they're built again.
- A cover letter in a template of your own with no letter layout prints in the template's own serif or sans-serif font, if it carries one, when the computer doesn't have the font its Word files use, such as Garamond on a Mac. Before, it printed in the computer's stand-in for that font, such as Times, which could join letters as above. A font the computer has is used as before.
- Letters copied into a resume or cover letter as one character, such as "ﬁ" in text from some PDFs, are written as the letters, in the PDF and the Word file.

## 0.5.0 - 2026-10-16

### Added
- Save to Factwright, a browser extension for Chrome and Firefox. On a job's page, click its button, check the title, company and posting, and save it: the job lands in your job hunt as New, with its link and its posting as you saw it, through sync, from any computer, without Factwright open. Or press Alt+Shift+S, or right-click the page, to save it without opening anything; a page it isn't sure of, such as one whose company it can't tell, is left for the popup to check instead: Chrome opens it, and Firefox marks the button with "!" to click. It reads the job data sites publish, the layouts of the big job sites, or text you selected, so it saves postings that need a sign-in to see, LinkedIn's included, unless you turn that off and save LinkedIn jobs by their link alone. Factwright's own tools still never read LinkedIn. It reads a page only when you click it, and sends nothing until you save. Set it up once: sign in to sync, then approve linking it in Factwright on your computer, after checking both show the same emoji, or use a link code or your recovery key. What it saves is locked with your job hunt's key before it leaves the browser. It's in review at the Chrome Web Store and Firefox Add-ons.
- A job saved from the browser shows its posting in the job's Files, and Claude uses it: `job_details` names it, and `save_posting` copies it into the job's folder, so a LinkedIn job's posting reaches Claude without its tools reading LinkedIn.
- factwright.com/extension, a page for Save to Factwright: what it does, the three ways to save a job, what it reads and sends, and setting it up, with a button for each store. Each button says "Coming soon to the Chrome Web Store" or "Coming soon to Firefox Add-ons" until that store approves the extension, then links to its listing. Every page's footer links to the page, and so do the home page and the download pages, which say it's coming soon until a store has it. A link to it in a chat or a feed shows a card of its own.
- The Add job dialog and Sync settings link to Save to Factwright's page, for saving jobs from your browser.
- factwright.com counts downloads, and the sync server counts how much sync is used, so Factwright's maker can see how it's doing. Each download is counted by computer, version and when, and nothing about who downloaded it is kept, not even an IP address. Once a day, the sync server counts its accounts and sign-ins, and keeps only those totals. `pnpm --filter @factwright/site stats` shows both, with a token that can read analytics and nothing else. The app itself still reports nothing, and the privacy policy says all this, from October 15.

### Changed
- The approval page for signing in names Save to Factwright when it's the extension asking, and the account page lists the extension as "Save to Factwright in Chrome on Mac".

### Fixed
- A job whose company or title is very long gets an ID short enough for a folder's name on every computer, and a company with no Latin letters, such as 株式会社, gets one from the job's link, so two such jobs don't share one. Sync now passes over a file it could never write on a computer, and keeps syncing the rest, where before one could stop it.
- The sync server's daily backup no longer stops partway when another part of its daily job fails, such as clearing out sign-ins that ended. Before, such a failure could end the job with most accounts not yet backed up that day. A backup that fails for any account now marks the run as failed too, and each failure is written down as it happens.
- The sync server removes a file's locked contents once nothing needs them, even when its storage fails the first time it tries: a later daily cleanup finishes. Before, a failed try left them on the server until the account was deleted, past the 90 days the privacy policy keeps earlier versions.

## 0.4.0 - 2026-10-15

### Added
- An ATS X-ray for every resume. The ATS X-ray button beside each resume in a job's Files, and beside each starting resume in Profile, shows what an applicant tracking system reads in it, worked out on your computer from the PDF or Word file itself, with no Claude. The text in the order a parser gets it sits beside what it fills in (your name and contact details, each job's title, company and dates, schools and skills), the sections it knows, and checks for what trips parsers up: text read out of order, columns, headers and footers, junk characters and icons, letters joined into one or spaced apart, tables and text boxes, missing contact details, dates it can't read, fonts and length. For a job's resume it also checks the posting's must-have and nice-to-have terms. A missing skill your fact bank backs plainly says Add it. One with a note beside it, an unverified fact, or a certification or license your profile lists says Check it first, quoting your words. One it doesn't back is a real gap that stays off.
- Send for revision, from a job's resume X-ray. Its Revise tab lists what the X-ray found, each with a checkbox, and what your Claude can fix as it is, such as dates parsers miss or a term your fact bank backs, starts ticked. Terms to check and real gaps wait for you to pick them: your Claude asks about each before adding it, and a yes is saved as a fact to verify. For what comes from the template, pick Fix my template, which changes it for every resume that uses it once you OK the change, or Use a template that reads cleanly, for this job alone. Factwright keeps the previous version in the job's folder, and the X-ray then shows what got fixed, such as "2 of 2 fixed · 8 of 8 key terms", beside what it read before. Only the findings' IDs, with none of the posting's words, are typed into the run, which reads what they say through a tool of its own and can't reach the web. A resume that went out with an application stays as sent, a revision needs the job's resume data, and revisions run at the tailored resume's levels.

## 0.3.0 - 2026-10-15

### Added
- Your fact bank grows as your Claude writes. While it tailors a resume, answers an application's questions or gets you ready for an interview, it asks about what the job wants that your facts don't show, when you likely have it, and for a missing number a claim needs. A yes is saved as a new fact to verify, with the question and your answer word for word, and a no goes under Doesn't have, so you're never asked again. The task uses your answers right away, and says which lines rest on them. It asks with no permission prompts: Factwright's own tools save only answers you gave in that run, as Claude Code reported them, so a job post can't plant a fact.
- The Fact bank opens with **Unverified**: the facts from your answers and the ones drafted from your files, each with where it came from, such as "Your answer while tailoring a resume for Acme, Oct 14", and the question and your answer. Verify one as it is, edit it (saving verifies it), or delete it. Until you do, your Claude asks before using it: Use and verify, Use this once, or Don't use. The sidebar shows how many wait, and a task that saved some says so in Claude's panel, with Verify them.
- **Things you've said you don't have**, in the Fact bank's gaps, each with your answer and when. Remove one that's changed, and your Claude can ask about it again.
- Fit checks note what's worth asking you, which a job's Fit section shows under Gaps, for the tailored resume to ask before it's written. A fit check itself still never asks.
- Cover letters. A Cover letter button on each job, beside Tailored resume, has your Claude write one in your own voice, from your facts and everything on file for the job: the posting, the fit check's research and what people say about the company, and your notes and calls. It's addressed to the hiring manager when one is on file, leads with your two or three strongest matches, with their numbers, and closes with a concrete next step. It asks about what the job wants that your facts don't show, and saves your answers as facts to verify, as a tailored resume does, then checks every line against your facts, and for clichés such as "I am writing to apply". It's built as a one-page PDF or Word file in the job's resume template, with the same header, fonts and colors, so the two look like a set. A template of your own without a letter layout prints it plainly, in its fonts and colors. The job's panel shows the letter, with Copy text for an application form's cover letter box, and its files to preview and open. A posting that asks for a cover letter makes writing one the job's next step. Your phone shows it too, once the sync server is updated. Cover letters run at the writing's levels, and Claude settings can change them.

### Changed
- Facts that wait for you are called unverified everywhere, and verified once you say so: on the Fact bank, in Profile, and in what your Claude says. The tag in your files stays `unconfirmed`, so your fact bank reads as before.
- Classic and Minimal lay out a cover letter under the resume's own header, and a template of your own can have a letter layout too. Making a template prints a cover letter in it beside the resume, for your Claude to check. A template file with a letter layout needs this version or later; one without works in earlier versions too.
- factwright.com makes supporting Factwright easy to find: a Support Factwright block under the code, with a button each for Buy Me a Coffee and GitHub Sponsors, and a link to it in every page's footer. Before, it was a line of text at the end of a section.

### Fixed
- A resume's Word file no longer comes out unreadable when its text holds an invisible control character, such as one pasted in with a posting's words. Word files leave those out now.

## 0.2.0 - 2026-10-14

### Added
- Link a new computer or browser without typing a code: approve it from a computer that's set up. Sign in to sync on the new one, and Factwright on your other computer shows that a device wants to link. Check both show the same six emoji, say so on each, and it's linked, with your key sealed so the server can't open it. Only the Factwright app approves, never a browser. - Dated notes: jot down what was said on a call or in an interview as you go. Each note is dated today, or the day you pick, newest first, and syncs. Your notes from before stay at the end. Claude reads them all with `job_details`, so interview prep and tailored resumes can use them.
- Your journey draws its flow chart in the app, as a view beside the summary. Copying it for sankeymatic.com stays.
- `@factwright/core`: the flow chart's layout, each job's search runs, dated notes, and the views' names and order.
- The fact bank has a page of its own. Read your facts file by file, search them all at once, or see together the ones still to confirm. A fact changes in a form: its title, the words resumes use, its status, ownership and confidence, and its details. You can also confirm a fact, delete one, add one, or change the sections around them, such as an overview. A change touches only that fact, and the rest of its file stays exactly as it was. If Claude or another computer changes a fact while you have it open, yours waits until you save again. Your Claude goes by your changes from its next task.
- `@factwright/core`: reading the fact bank's files a heading at a time, and changing, adding, deleting or confirming a claim while the rest of its file stays as written.
- When more than one of your templates fits a job, such as two for any job, a tailored resume uses the one that suits the role, by what your guide says each is for, and says which it picked.
- Installers: one Mac disk image for Apple silicon and Intel, and a Windows installer that needs no administrator. Releases are signed and notarized, then published to downloads.factwright.com by a workflow when a version is tagged. The installed app is locked down with Electron's fuses, and keeps the same data folder as before. Factwright's first version is 0.1.0.
- Updates: an installed copy looks for a new version every ten minutes, and as soon as you come back to it, downloads it in the background, and shows **Update ready** at the bottom of the sidebar, with what's new. It installs when you restart, or the next time you quit, and asks first if you're writing a fact or a note you haven't saved.
- The website offers the download for your computer, with the other one a link under it.
